# Бот «домашка → ігри»: передача контексту

Документ для нової (локальної) сесії Claude Code. Тут усе, що вже з'ясовано й зроблено
в попередній хмарній сесії, щоб не починати з нуля.

## Мета

Дитина (6 клас) має домашні завдання в Google Classroom. Інтернет дитини фільтрується
через **AdGuard DNS** (хмарний, підписка Personal), пристрої дитини підключені до
нього через роутер **Keenetic**. Батько хоче:

1. Автоматично перевіряти, чи всі свіжі завдання в Classroom здані.
2. Якщо так — автоматично відкривати ігри в AdGuard DNS; якщо ні — тримати закритими.
3. Отримувати звіти й керувати вручну з Telegram (кнопки).
4. Позначати виключення: завдання, які здані в класі, але висять у Classroom
   «для тих, хто не встиг», мають рахуватися виконаними.

Спілкування з користувачем — українською.

## Що з'ясовано (обмеження)

- Акаунт дитини — **шкільний Google Workspace for Education, позначений як «до 18»**.
  Сторонні OAuth-застосунки (OAuth Playground, власний Cloud-проєкт) **заблоковані**
  («Немає доступу до цього сервісу… адміністратор указав, що їм не виповнилося 18»).
- **Google Apps Script усередині акаунта дитини працює** — це «внутрішній» скрипт,
  блокування на нього не поширюється. Сервіс Classroom API v1 додається як advanced service.
- **Обов'язково** явно задавати `oauthScopes` у `appsscript.json`. Без цього Apps Script
  сам підбирав «вчительські» scopes, і виклики падали з
  `The caller does not have permission`. З `classroom.coursework.me.readonly` — працює.
- `Classroom.Courses.CourseWork.list` для учня падав з permission denied, тому скрипт
  бере список незданих робіт через `StudentSubmissions.list(courseId, '-', {userId: 'me'})`,
  а деталі кожної — через `CourseWork.get` (з fallback на поле `late`, якщо й це заборонено).
- Терміни (`dueDate`/`dueTime`) у Classroom — у UTC; конвертація в коді перевірена,
  показує правильний київський час (напр. «19.10 23:59»).
- Часовий пояс у маніфесті: `Europe/Kiev`.
- AdGuard DNS: розклад у батьківському контролі — це **«пауза»** (у задані інтервали
  обмеження знімаються). Є блокування окремих сервісів і **категорій** сайтів.
- Хмарна сесія не мала доступу до `adguard-dns.io` / `api.adguard-dns.io` (мережева
  політика). Специфікацію користувач вставив вручну; нижче — витяг потрібного.

## Архітектура

```
[Скрипт 1: Apps Script у шкільному акаунті дитини]  --POST статус-->  [Скрипт 2: Apps Script у особистому акаунті батька]
  - кожні 15 хв (13–21) перевіряє Classroom                             - вебзастосунок doPost приймає статус (з SECRET)
  - Telegram-бот №1: звіти + кнопки «✔️ зараховано»                     - тримає ключ AdGuard API
  - таблиця виключень (Google Sheet на Диску дитини)                    - відкриває/закриває ігри на сервері «Дитина»
                                                                         - Telegram-бот №2: кнопки Відкрити/Закрити/Авто/Статус
```

- Ключ AdGuard дає повний доступ до акаунта, тому **не** зберігається в акаунті дитини.
- Два окремі Telegram-боти, бо обидва скрипти читають `getUpdates` і конфліктували б.
- Скрипт 2 вирішує: override (вручну) → поза `GAME_HOURS` закрито → немає свіжого статусу
  (> 40 хв) закрито → інакше відкрито, якщо все здано. Викликає AdGuard лише при зміні стану.
- Відомий компроміс: SECRET лежить і в скрипті дитини, теоретично можна підробити
  «все здано»; батько отримує сповіщення про кожне відкриття.

## Статус

| Що | Стан |
|---|---|
| Скрипт 1: перевірка Classroom (`preview`) | ✅ працює, показує правильний список |
| Скрипт 1: Telegram-бот №1, звіти (`saveSettings`, `check`, `setup`) | ✅ працює, звіти приходять |
| Скрипт 1: виключення (таблиця + кнопки «✔️») | ❓ код написано, **невідомо, чи користувач його встановив** — уточнити |
| Скрипт 1: `reportToParent` / `connectParent` | ⏳ код є в `child-script/Code.gs`, ще не встановлено |
| Скрипт 2 (`parent-script/Code.gs`) | ⏳ написано за специфікацією, **не запускалося жодного разу** |
| Ключ AdGuard API, бот №2, вибір ID ігор | ⏳ не зроблено |

Актуальний код обох скриптів — у цій папці. Користувач вставляє код в редактор
Apps Script вручну (з телефона/ПК). Альтернатива для локальної сесії — `clasp`
(`npm i -g @google/clasp`), але логін потрібен окремо для кожного Google-акаунта,
а для шкільного акаунта «до 18» clasp, ймовірно, теж заблокований як сторонній застосунок.

## AdGuard DNS API — витяг зі специфікації (v1.17.3)

База: `https://api.adguard-dns.io`, заголовок `Authorization: ApiKey <key>`
(ключ: кабінет → налаштування користувача → API-ключі). Повна специфікація:
`https://api.adguard-dns.io/swagger/openapi.json`.

- `GET /oapi/v2/dns_servers?limit=100` → `{items: [DNSServer], navigation}`;
  `DNSServer = {id, name, default, devices_count, settings: DNSServerSettings}`.
- `GET /oapi/v1/dns_servers/{id}/settings` → `DNSServerSettings`.
- `PUT /oapi/v1/dns_servers/{id}/settings` з `DNSServerSettingsUpdate` (часткове оновлення):
  ```json
  {"parental_control_settings": {
     "blocked_services": [{"id": "roblox", "enabled": true}],
     "blocked_filtering_categories": [{"id": "games", "enabled": true}]
  }}
  ```
  `enabled: true` = заблоковано. У відповіді GET **немає** `blocked_filtering_categories`
  (є лише в Update-схемі), тож поточний стан категорій прочитати не можна.
  Невідомо, чи `blocked_services` в PUT замінює весь список, чи мерджить — код
  надсилає повний список із зміненими пунктами, що безпечно в обох випадках.
- `ParentalControlSettings`: `enabled`, `block_adult_websites_enabled`,
  `engines_safe_search_enabled`, `youtube_safe_search_enabled`, `blocked_services[]`,
  `screen_time_schedule` (`daily_schedule[]` з `day_of_week`, `periods[{start,end}]`).
- Довідники: `GET /oapi/v1/parental_control_categories` → `[{id}]`;
  `GET /oapi/v1/web_services` → `[{id, name, icon_svg}]`.
- Пристрої: `GET /oapi/v2/devices` (`dns_server_id` у кожного), `PUT /oapi/v1/devices/{id}`
  з `{dns_server_id}` — можна перекидати пристрій між серверами (альтернативний спосіб
  керування: два сервери «ігри можна» / «ігри не можна»).

## Наступні кроки

1. Уточнити в користувача, чи встановлена версія скрипта 1 з виключеннями.
2. Крок А: користувач створює ключ AdGuard API, перевіряє сервер «Дитина»
   (пристрої дитини прив'язані, батьківський контроль увімкнено), створює бота №2.
3. Крок Б: скрипт 2 в особистому акаунті батька: `saveSettings` → `listIds` →
   заповнити `GAME_SERVICES`/`GAME_CATEGORIES` (запитати, в які ігри грає дитина) →
   `testClose`/`testOpen` (перевірити на пристрої дитини) → `setup` → розгорнути
   вебзастосунок (Виконувати як: Я; Доступ: Усі) → скопіювати URL.
4. Крок В: оновити скрипт 1 до версії з цієї папки, запустити `connectParent` з URL і SECRET.
5. Якщо AdGuard поверне помилку на PUT — розібрати текст помилки, звіритися зі специфікацією.
   Локальна сесія може сама викликати API через curl, якщо користувач дасть ключ у змінній
   середовища (не в чат і не в репозиторій).

## Безпека

- Токени ботів, ключ AdGuard, SECRET і URL вебзастосунку **ніколи** не комітити.
  У коді — лише заглушки `ВСТАВ_…`; значення зберігаються у Script Properties.
- Після одноразового запуску функцій налаштування — повертати заглушки в код.
